# VideoForge 多语言视频再创作系统：技术设计文档

版本：0.1（方案基线）  
调研日期：2026-07-19  
首期验证环境：macOS；目标运行环境：macOS / Windows / Linux  
首期平台：抖音 + TikTok  
首期内容方向：AI、科技、数码资讯  
首期语言：中文 ↔ 英文

## 1. 文档用途

这是一套可以直接交给 Coder Agent 逐阶段实施的设计包。它覆盖：

- 热点发现与排序
- 视频获取、去重和素材溯源
- ASR、OCR、镜头、人物、画面语义分析
- “结构重写”与“原片重剪”两种再创作模式
- 热门片段识别、自动剪辑、模板化渲染
- 中英文字幕、画面文字、配音、口型适配
- 人审/自动审配置
- 官方 API、浏览器、Android 真机三层发布适配
- 发布后的数据回收和模板学习
- 自托管控制中心 + 桌面端边缘工作节点

本包不是单一脚本的拼装，也不建议 fork 某个现成项目后继续堆功能。实施时应先建立稳定的领域模型、时间线中间表示和连接器协议，再按模块接入开源能力。

## 2. 已确认的产品决策

| 维度 | 决策 |
|---|---|
| 产品形态 | 自托管开源平台 + 桌面创作工具 |
| 运行拓扑 | 中央控制中心 + 桌面边缘 Worker |
| MVP 全链路 | 热点 → 下载 → AI 拆解 → 二创 → 多语言 → 发布 → 数据反馈 |
| 首期平台 | 抖音、TikTok |
| 二创方式 | 结构重写生成新稿；原视频重剪 |
| 素材来源 | 授权原片、自有素材库、商业素材、AI 图/视频、数字人，均以 Provider 配置 |
| 计算策略 | FFmpeg/OCR/ASR/轻模型本地优先；LLM/VLM/生成式视频/高质量口型云端按需 |
| 审核策略 | 按账号/模板配置；新模板默认人审，稳定模板可自动发布 |
| 发布策略 | 官方 API 优先，浏览器自动化次之，Android 真机自动化兜底 |
| 剪辑核心 | FFmpeg + Remotion + OpenTimelineIO；剪映/CapCut 与 DaVinci 仅作为导出适配器 |
| 首期规模 | 1–5 个账号，最多约 20 条视频/日 |
| 首期验证 | 仅 macOS；代码不得硬编码 macOS 专属业务逻辑 |

## 4. Coder Agent 执行规则

1. 先实现 `implementation/53-coder-agent-roadmap.md` 中的 P0，不得从 UI 或某个平台爬虫直接开工。
2. 所有外部平台、模型和素材源必须实现 Provider/Connector 接口；业务模块不得直接依赖某个项目的内部结构。
3. 所有媒体操作都必须产出可重放的 Job Manifest、输入哈希、工具版本和产物哈希。
4. 时间线以内部 `CreativeTimeline` + OTIO 映射为真值；CapCut/剪映草稿不是系统真值。
5. 长任务必须可暂停、恢复、重试和幂等；不得只靠进程内队列。
6. UI 不能保存明文平台凭据；macOS 使用 Keychain，服务端使用加密 Secret Store。
7. 浏览器或真机遇到登录失效、验证码、风控挑战时转入 `WAITING_FOR_HUMAN`，不得尝试绕过。
8. 可见水印/遮挡物清理仅对已获授权素材启用，并保留原始来源和处理记录。
9. GPL/AGPL 或特殊许可证项目不得直接复制进宽松许可证核心；按 `20-open-source-landscape.md` 的隔离策略执行。
10. 每个阶段必须通过对应验收测试后再进入下一阶段。

## 5. 文档中的优先级

- `P0`：架构地基，缺失会导致后续返工。
- `P1`：MVP 必须。
- `P2`：MVP 后增强。
- `P3`：规模化或商业化阶段。

## 6. 责任边界

系统以授权内容、原创内容和许可素材为默认工作对象。合规/版权判断设计成可插拔策略模块，不阻塞首期技术验证；但素材来源、授权声明、模型/字体/音乐许可证与发布审计记录必须从第一天保留，避免后续无法补齐溯源链。

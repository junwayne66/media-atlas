# Feature Specification: 可恢复的采集 Worker

**Feature Branch**: `[002-ingest-worker]`

**Created**: 2026-07-27

**Status**: Draft

**Input**: User description: "集成 recipe-studio-ingest-docs 采集 Worker 设计文档并在当前项目中实现"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 发现并解析来源内容 (Priority: P1)

内容运营人员提交抖音关键词或公开内容链接后，系统异步完成离线可验证的发现或解析任务，并将结果标准化为可检索、可去重、可追溯的来源记录。实时平台能力未配置时，系统必须明确转为人工处理，不得伪造成功或静默返回空数据。

**Why this priority**: 稳定获得标准化来源记录是采集链路的入口，也是后续授权、下载和分析的前提。

**Independent Test**: 使用脱敏的搜索、详情、短链、空结果和挑战 Fixture 创建任务，验证每个任务都得到标准化来源记录或明确的人工/失败处置，且重复输入不产生重复事实。

**Acceptance Scenarios**:

1. **Given** 一个受支持的抖音规范链接，**When** 用户创建解析任务，**Then** 系统返回任务标识，并最终建立或复用唯一的来源记录。
2. **Given** 一个抖音短链且实时展开未启用，**When** 用户创建解析任务，**Then** 任务明确说明需要人工展开，而不是访问网络或伪造规范链接。
3. **Given** 一个关键词搜索 Fixture，**When** Worker 处理发现任务，**Then** 结果按内容标识或规范链接去重并保存公开元数据。
4. **Given** 页面明确无搜索结果，**When** Worker 完成任务，**Then** 任务成功且结果数为零；若页面结构无法识别，则以稳定错误码失败。

---

### User Story 2 - 经授权获取原始媒体 (Priority: P2)

内容运营人员只有在提交明确的素材使用依据后，才能创建原始媒体获取任务。系统校验媒体完整性、生成不可变资产记录并保留来源、授权、工具和哈希证据；没有授权时只能保留公开元数据。

**Why this priority**: 原始媒体是下游分析的输入，但必须先满足使用依据与审计边界。

**Independent Test**: 使用本地合成媒体 Fixture 分别提交 UNKNOWN 与允许的使用依据，验证前者零资产、后者生成可读取且带哈希和审计信息的资产，并验证重复获取不重复保存二进制。

**Acceptance Scenarios**:

1. **Given** 来源的使用依据为 UNKNOWN，**When** 用户请求获取原始媒体，**Then** 系统拒绝创建获取任务且不产生任何对象。
2. **Given** 调用者提交允许的使用依据和说明，**When** 获取任务使用合成媒体 Fixture 完成，**Then** 系统保存不可变媒体资产、完整性证据与授权审计。
3. **Given** 同一内容已有可访问的同哈希资产，**When** 用户再次请求普通获取，**Then** 系统复用已有资产。
4. **Given** 强制重新获取得到不同哈希，**When** 任务完成，**Then** 系统创建新版本资产并保留旧资产。

---

### User Story 3 - 处理挑战并人工恢复 (Priority: P3)

当浏览器会话失效、出现验证码或风险验证时，Worker 停止自动执行，保存脱敏现场并将任务交给人工；操作人员处理完受控浏览器后显式恢复任务，系统从安全、幂等的步骤重新执行。

**Why this priority**: 平台访问控制不可预测，人工接管是避免绕过限制和无限重试的必要安全边界。

**Independent Test**: 使用静态挑战页面 Fixture 触发人工等待，验证截图/现场摘要、状态转换、零自动重试和显式恢复；全程扫描 Cookie/Token Canary 不得出现在数据、事件或日志中。

**Acceptance Scenarios**:

1. **Given** Worker 检测到登录失效或验证页面，**When** 当前任务处理中，**Then** 任务进入等待人工状态并记录脱敏原因和调试资产。
2. **Given** 一个等待人工的任务，**When** 操作人员显式恢复，**Then** 任务重新排队并从完整的幂等步骤开始。
3. **Given** 一个非等待人工状态的任务，**When** 用户请求恢复，**Then** 系统拒绝非法状态转换。
4. **Given** 任务被取消，**When** Worker 或操作人员再次处理，**Then** 系统保持取消终态且不产生业务副作用。

---

### User Story 4 - 可恢复且可审计地运行采集任务 (Priority: P4)

运维人员能够查询任务、事件与结果；多个 Worker 并发运行时同一任务只会被一个 Worker 处理，Worker 崩溃或租约过期后任务可以安全恢复，所有关键状态变化都有不可变审计证据。

**Why this priority**: 采集是耗时且易受外部环境影响的工作，恢复能力和审计性决定其是否可用于持续运营。

**Independent Test**: 使用两个本地 Worker 并发领取任务，并模拟处理中断、租约过期、暂时错误、永久错误和取消，验证不重复处理、按策略恢复及事件顺序。

**Acceptance Scenarios**:

1. **Given** 两个 Worker 同时请求任务，**When** 队列中只有一个任务，**Then** 只有一个 Worker 获得该任务。
2. **Given** 一个可幂等任务的 Worker 租约过期，**When** 恢复器运行，**Then** 任务可以重新分配且不会重复产生来源或资产。
3. **Given** 暂时性错误，**When** 尝试次数未耗尽，**Then** 任务按有界退避重新执行。
4. **Given** 永久错误或尝试次数耗尽，**When** 任务结束，**Then** 任务以稳定错误码失败并保留完整事件记录。

### Edge Cases

- URL 包含用户信息、混淆主机、非 HTTP 协议、内网地址或重定向到内网目标时必须拒绝。
- 同一内容没有平台内容 ID 时，使用规范链接的稳定身份进行去重。
- 页面明确空结果与解析器漂移必须使用不同结果语义。
- Profile 已被其他任务占用时，任务应有界等待或返回稳定的繁忙错误，不得并发打开同一会话。
- 媒体响应超出大小限制、MIME 不受支持、长度不一致或无法探测时，不得生成可用资产。
- 对象存储成功但业务记录失败时，孤儿对象必须可发现并安全清理。
- 任务取消、人工恢复和租约过期同时发生时，终态与乐观并发规则必须防止旧 Worker 覆盖新状态。
- 所有错误、事件和调试资产均不得包含 Cookie、Authorization、临时媒体查询令牌或口令。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将内容发现、URL 解析和原始媒体获取建模为相互独立的操作。
- **FR-002**: 第一阶段 MUST 只支持抖音来源；TikTok、Android、发布与下游理解不在本功能范围内。
- **FR-003**: 系统 MUST 通过可替换的来源适配器输出平台无关的标准化内容事实，上层不得依赖平台原始字段。
- **FR-004**: 默认运行模式 MUST 使用离线 Fixture、Fake 或 Manual Adapter；不得要求真实平台账号、生产 Cookie、付费凭据或线上平台访问。
- **FR-005**: 系统 MUST 保存搜索意图、标准化来源、原始公开元数据、首次发现时间和最近观察时间。
- **FR-006**: 来源 MUST 按平台内容标识优先、规范链接身份兜底进行幂等去重；并发相同输入不得产生重复事实。
- **FR-007**: 搜索 MUST 具有最大结果数、最大滚动轮数、连续空闲轮次和总时间预算等有界停止条件。
- **FR-008**: 页面明确无结果 MUST 被视为成功空结果；无法识别预期页面结构 MUST 返回稳定的解析器漂移错误。
- **FR-009**: 系统 MUST 集中检测登录失效、验证码和风险验证，并将其转为等待人工，不得自动破解或绕过。
- **FR-010**: 等待人工前 MUST 保存脱敏的当前地址、页面标题、Profile 引用、时间、原因与可选调试资产。
- **FR-011**: 人工恢复 MUST 仅允许从等待人工状态发起，并从安全、幂等的完整步骤重新执行。
- **FR-012**: 原始媒体获取 MUST 要求使用依据为 OWNED、LICENSED、USER_PROVIDED 或 INTERNAL_APPROVED；UNKNOWN MUST 被拒绝且零对象写入。
- **FR-013**: 使用依据变化、强制重新获取、人工恢复和取消 MUST 形成不可变审计事件，且记录操作者、时间与可选说明。
- **FR-014**: 媒体获取 MUST 执行大小、长度、允许类型、哈希和可读性校验，未通过时不得生成可用资产。
- **FR-015**: 原始媒体资产 MUST 不可变；相同哈希复用，不同哈希创建新版本，禁止覆盖旧对象。
- **FR-016**: 系统 MUST 提供孤儿对象发现与清理能力，并默认只清理由采集命名空间创建且超过安全窗口的对象。
- **FR-017**: 采集任务 MUST 支持异步创建、查询、取消、人工恢复、有界重试、租约心跳、崩溃恢复和幂等结果提交。
- **FR-018**: 并发 Worker MUST 保证同一任务在同一时刻只被一个有效租约处理，过期 Worker 不得覆盖新租约结果。
- **FR-019**: 每次任务状态变化 MUST 写入不可变事件，并使用稳定错误码区分暂时错误、人工错误与永久错误。
- **FR-020**: 系统 MUST 提供来源、任务、事件、媒体资产和 Source Profile 元数据的查询能力。
- **FR-021**: Source Profile MUST 只保存业务描述和不透明安全存储引用；Cookie、Authorization 和会话明文不得进入 API、业务数据库、任务信封或日志。
- **FR-022**: URL 解析与每一步重定向 MUST 重新执行协议、域名和公共地址校验，并拒绝内网、环回、链路本地、文件与非 HTTP(S) 目标。
- **FR-023**: 采集日志 MUST 为结构化日志，并至少可关联请求、任务、Worker、平台、Profile、来源和稳定错误码。
- **FR-024**: 系统 MUST 公开存活与就绪状态，并能诊断数据库、对象存储、任务积压、陈旧租约、解析器错误和挑战增长。
- **FR-025**: 测试 MUST 使用合成或脱敏 Fixture，不得使用真实平台账号或生产 Secret；任何手工线上验收必须显式开启并默认关闭。

### Key Entities

- **Discovery Query**: 一次用户搜索意图，包含平台、关键词、数量上限、可选时间过滤、Profile 引用和创建者。
- **Source Content**: 一条标准化平台内容事实，包含平台身份、规范链接、作者、标题、公开统计、原始元数据、发现时间、状态和当前使用依据。
- **Ingest Job**: 发现、解析、获取或会话检查操作的异步执行记录，包含状态、尝试、租约、幂等键、结果和稳定错误。
- **Job Event**: 任务状态与关键审计行为的不可变事件。
- **Media Asset**: 经过完整性校验的不可变原始媒体版本，包含对象引用、哈希、大小、类型、探测信息、获取时间和来源。
- **Rights Attestation**: 调用者提交的素材使用依据、说明、操作者和时间，不替代法律判断。
- **Source Profile**: 浏览器身份的业务元数据和不透明安全存储引用，不包含会话明文。
- **Debug Artifact**: 挑战或解析错误现场的脱敏截图、摘要或短时 Trace，具有独立保留策略。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一组至少 50 个规范链接、短链、无效输入和本地 Fixture 中，100% 得到“已解析、明确人工处理或结构化失败”之一，静默失败为零。
- **SC-002**: 同一来源在顺序重复 10 次和两路并发导入时均只产生一条标准化来源事实。
- **SC-003**: 所有 UNKNOWN 使用依据的获取请求均被拒绝，测试对象存储新增对象数为零。
- **SC-004**: 经允许使用依据提交的合成媒体 100% 生成可读取、哈希非空、来源和授权证据完整的资产。
- **SC-005**: 两个并发 Worker 对 100 个本地任务的重复领取数为零；模拟租约过期后所有可幂等任务均能恢复到终态。
- **SC-006**: 所有挑战 Fixture 均进入等待人工且自动快速重试次数为零，显式恢复后能重新排队。
- **SC-007**: 向输入、异常和调试上下文注入敏感 Canary 后，API 响应、业务表、任务事件、对象元数据和日志中的 Canary 命中数为零。
- **SC-008**: 协议混淆、内网主机、DNS 解析到私有地址及重定向到私有地址的测试请求拒绝率为 100%。
- **SC-009**: API、Worker、数据库、对象存储和现有控制台能通过一条本地启动流程运行，健康检查全部成功。

## Assumptions

- 当前仓库的领域分层、生成合同、对象存储、Worker Task Lease、Temporal 长流程和现有 SourceAsset 聚合继续作为系统真值；外部文档中的独立 PostgreSQL `crawl_jobs` 队列概念映射到现有任务与工作流能力，不修改核心 ADR。
- 当前仓库面向通用短视频二创而非菜谱专属场景，因此关键词和内容模型保持领域中立。
- 浏览器自动化只作为隔离的可选适配器存在；第一阶段交付以离线 HTML/JSON Fixture、Fake 获取和人工导入完成自动化验收。
- Profile 实体由 Desktop/Edge 侧安全存储拥有，控制面只接收不透明 handle；Web API 不上传 Cookie。
- 现有对象存储、数据库、身份验证和本地安全设置能力被复用，不新增独立基础设施服务。
- 手工启用真实 Douyin Profile、线上解析或下载属于项目停止条件，需要另行提供账号、凭据、许可证确认和显式授权。

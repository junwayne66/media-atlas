# Feature Specification: 本地安全设置与账号绑定

**Feature Branch**: `[001-secure-local-settings]`

**Created**: 2026-07-27

**Status**: Draft

**Input**: User description: "补全项目设置页的设置选项，配置LLM、ASR、VLM、真实平台账号绑定等等，配置后的敏感信息被妥善保存到本地"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 初始化并解锁本地凭据库 (Priority: P1)

作为本地单机操作者，我希望首次进入设置页时创建凭据库口令，后续在需要查看或修改敏感配置时解锁凭据库，从而确保 API Key、Token 和账号凭据不会以明文持久化。

**Why this priority**: 没有安全的秘密存储，任何 Provider 或平台账号配置都会违反项目的凭据安全红线。

**Independent Test**: 在全新数据库中初始化凭据库，保存一个测试秘密，重启服务后确认凭据库自动锁定、数据库和 API 响应不含明文，使用正确口令解锁后仍可更新该秘密。

**Acceptance Scenarios**:

1. **Given** 本地凭据库尚未初始化，**When** 用户提交满足强度要求且两次一致的口令，**Then** 凭据库完成初始化并进入已解锁状态，口令本身不被持久化。
2. **Given** 凭据库已初始化且服务刚重启，**When** 用户打开设置页，**Then** 页面显示“已锁定”，非敏感配置仍可查看，敏感配置不能新增、修改或使用。
3. **Given** 凭据库已锁定，**When** 用户提交错误口令，**Then** 系统拒绝解锁且不修改任何已保存数据。
4. **Given** 凭据库已解锁，**When** 用户主动锁定，**Then** 进程内解密能力立即失效，已保存密文不受影响。

---

### User Story 2 - 配置 AI Providers (Priority: P1)

作为内容工作流操作者，我希望在设置页配置 LLM、ASR 和 VLM 的启用状态、Provider、模型、服务地址、非敏感参数和凭据，以便后续工作流通过统一配置选择实际 Provider。

**Why this priority**: LLM、ASR 和 VLM 是分析与创作链路的基础能力，也是用户明确要求的主要设置项。

**Independent Test**: 分别创建 LLM、ASR 和 VLM 配置，刷新页面和重启服务后确认非敏感配置保留、秘密只显示“已配置”状态且从未被回显。

**Acceptance Scenarios**:

1. **Given** 凭据库已解锁，**When** 用户保存 LLM、ASR 或 VLM 配置和 API Key，**Then** 页面显示保存成功、Provider 配置可见、秘密仅显示已配置状态。
2. **Given** 某 Provider 已有秘密，**When** 用户仅修改模型或服务地址且不填写新秘密，**Then** 原秘密保持不变。
3. **Given** 某 Provider 已有秘密，**When** 用户明确清除秘密，**Then** 该秘密不可再使用且页面显示未配置。
4. **Given** 两个页面会话同时修改同一配置，**When** 后提交者使用过期版本保存，**Then** 系统返回冲突并要求刷新，不静默覆盖新配置。

---

### User Story 3 - 保存真实平台账号绑定材料 (Priority: P2)

作为发布操作者，我希望为抖音和 TikTok 保存账号显示名、平台账号标识、绑定方式及必要的凭据引用，以便发布模块以后通过不透明凭据引用使用正确账号，同时避免把平台秘密暴露给 Web 页面或业务合同。

**Why this priority**: 账号绑定是从 Fake-first 骨架走向真实发布的必要准备，但在线 OAuth、验证码和平台审核仍受停止条件约束。

**Independent Test**: 新增抖音和 TikTok 账号绑定，验证列表仅返回账号元数据、绑定状态和秘密配置状态；数据库中找不到提交的 Token 明文；删除绑定后对应秘密一并失效。

**Acceptance Scenarios**:

1. **Given** 凭据库已解锁，**When** 用户保存官方 API/OAuth 账号元数据和访问材料，**Then** 系统创建服务端加密的不透明凭据引用，账号状态明确显示“未在线验证”。
2. **Given** 账号已保存，**When** 用户刷新或重新进入页面，**Then** 页面可识别账号和绑定方式，但不能读取、复制或恢复原始秘密。
3. **Given** 账号绑定被删除，**When** 后续查询设置，**Then** 账号元数据和关联秘密均不再可用。
4. **Given** 用户选择浏览器 Cookie 或 Android 会话绑定，**When** 保存配置，**Then** 控制台只保存 Desktop Keychain/设备端 handle，不能接收或持久化 Cookie/设备会话明文，并明确提示需要在对应本地端完成。
5. **Given** 用户选择会触发验证码、风控或真实平台授权的绑定方式，**When** 保存配置，**Then** 系统只保存本地材料并明确提示需要人工完成真实平台验证，不尝试绕过或自动连接。

---

### User Story 4 - 安全管理和诊断配置 (Priority: P3)

作为本地操作者，我希望查看每类配置是否完整、最近更新时间和错误提示，并能安全地禁用或删除配置，从而在不暴露秘密的前提下排查环境问题。

**Why this priority**: 可诊断状态能防止“配置看似成功、实际不可用”的静默失败。

**Independent Test**: 对已配置、缺少秘密、已禁用、凭据库锁定和版本冲突等状态逐一渲染，确认每种状态均有明确、非敏感的说明。

**Acceptance Scenarios**:

1. **Given** Provider 缺少必要秘密，**When** 用户启用配置，**Then** 页面显示明确警告，不把它标记为可用于真实调用。
2. **Given** 配置被禁用，**When** 用户重新打开设置页，**Then** 非敏感配置仍保留且状态为已禁用。
3. **Given** 后端拒绝保存，**When** 页面展示错误，**Then** 错误信息不包含用户提交的任何秘密。

### Edge Cases

- 凭据库初始化请求并发到达时，只允许一个初始化成功，其余请求得到可恢复的冲突提示。
- 口令过短、空秘密、超长字段和不支持的 Provider/平台枚举必须被明确拒绝，错误响应不得回显原始秘密。
- 凭据库在保存秘密的过程中被锁定时，操作必须原子失败，不能留下元数据与秘密不一致的半成品。
- 更新配置但未提供新秘密时，必须区分“保持原秘密”和“明确清除秘密”。
- 删除配置或账号失败时，不能只删除元数据却残留可引用的孤立秘密。
- 数据库备份被读取时，只能看到服务端秘密的密文、随机材料、外部凭据 handle 和非敏感元数据，不能离线直接恢复秘密。
- 纯 Web 控制台不能录入 Desktop Cookie 或 Android 会话本体；该类凭据只能在 macOS Keychain Broker 或设备端写入。
- 服务重载、容器重启和多个 API Worker 不得把解锁口令或明文秘密写入磁盘；未解锁的 Worker 必须拒绝秘密操作。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在设置页提供凭据库“未初始化、已锁定、已解锁”三种明确状态。
- **FR-002**: 系统 MUST 允许本地操作者初始化、解锁和锁定凭据库，并且 MUST NOT 持久化解锁口令本身。
- **FR-003**: 系统 MUST 对 Provider 密钥、服务端 OAuth Token 和 Client Secret 执行认证加密后再持久化；浏览器 Cookie MUST 留在 Desktop Keychain，Android 会话 MUST 留在设备端，控制中心只保存不透明 handle。
- **FR-004**: 系统 MUST 在服务重启后默认保持凭据库锁定，直到用户再次提供正确口令。
- **FR-005**: 系统 MUST NOT 在设置 API 响应、错误详情、日志、浏览器本地存储或任务合同中返回或持久化明文秘密。
- **FR-006**: 系统 MUST 至少支持 LLM、ASR、VLM 三类 Provider 配置，包括启用状态、Provider 名称、模型名称、服务地址、非敏感参数和秘密配置状态。
- **FR-007**: 用户 MUST 能在不重新提交秘密的情况下修改 Provider 非敏感配置。
- **FR-008**: 用户 MUST 能明确替换或清除 Provider 秘密，并能禁用或删除 Provider 配置。
- **FR-009**: 系统 MUST 为配置提供版本号并在并发更新时执行冲突检测。
- **FR-010**: 系统 MUST 支持抖音和 TikTok 平台账号绑定元数据，包括显示名、平台账号标识、绑定方式、启用状态和秘密配置状态。
- **FR-011**: 平台账号绑定 MUST 只向业务模块提供不透明凭据引用，不能提供原始秘密。
- **FR-019**: Web 设置 API MUST NOT 接收 Desktop Cookie 或 Android 会话明文；DESKTOP/DEVICE 绑定只能登记已在对应安全存储中创建的 handle。
- **FR-012**: 平台账号在未执行真实平台校验前 MUST 显示“未在线验证”，不能被误报为已验证或可发布。
- **FR-013**: 删除 Provider 配置或平台账号绑定时，系统 MUST 同一事务删除或失效其关联秘密。
- **FR-014**: 凭据库锁定时，系统 MUST 允许读取非敏感设置，但 MUST 拒绝新增、替换、清除和使用秘密。
- **FR-015**: 系统 MUST 对口令和秘密设置合理的长度边界，并在校验失败时使用脱敏错误信息。
- **FR-016**: 设置页 MUST 为保存成功、凭据库锁定、缺少秘密、版本冲突、未在线验证和服务错误提供可区分的状态。
- **FR-017**: 系统 MUST 保留设置的创建时间、更新时间和不含秘密的配置状态，以支持本地诊断。
- **FR-018**: 本功能 MUST NOT 发起真实平台 OAuth、账号登录、验证码处理、模型调用或付费 API 请求。

### Key Entities

- **本地凭据库**: 表示本机秘密存储的初始化与锁定状态，包含口令派生参数和被认证加密包装的随机主密钥，不包含口令或明文密钥。
- **加密秘密**: 与某一用途和所有者关联的不可回显服务端敏感数据，持久化时仅保留密文和认证所需随机材料。
- **Provider 配置**: 某类 AI 能力的非敏感配置、启用状态、版本和可选的不透明凭据引用。
- **平台账号绑定**: 发布平台账号的非敏感身份信息、绑定方式、验证状态、版本和可选的不透明凭据引用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 2 分钟内完成凭据库初始化并保存首个 LLM、ASR 或 VLM 配置。
- **SC-002**: 对所有设置 API 响应、错误、应用日志、浏览器存储和数据库原始行的自动化检查中，提交的测试秘密明文出现次数为 0。
- **SC-003**: 服务重启后 100% 的测试场景均保持配置元数据可读、凭据库默认锁定，并且只有正确口令能恢复秘密操作能力。
- **SC-004**: LLM、ASR、VLM 三类 Provider 均可独立完成创建、刷新后读取、非敏感更新、秘密替换、秘密清除和删除。
- **SC-005**: 抖音和 TikTok 账号绑定均可完成创建、列表读取、更新和删除，且始终明确显示未在线验证。
- **SC-006**: 错误口令、过期版本和锁定状态下的秘密操作均能被 100% 拒绝，且不会造成部分写入或已保存配置损坏。
- **SC-007**: 设置页在空状态、已锁定、已配置、缺少秘密、版本冲突和后端错误下均提供可理解且不含敏感信息的反馈。

## Assumptions

- 首期面向单用户、本机 Docker Compose 环境；多租户权限与远程共享不在本功能范围。
- 凭据库使用用户自设口令解锁，口令只在当前 API 进程内短暂存在；服务或容器重启后需要重新解锁。
- 设置元数据和服务端密文保存在本机现有持久化数据库中；Desktop Cookie 由现有 macOS Keychain Broker 保存，Android 会话留在设备端。
- 抖音和 TikTok 的真实在线验证、OAuth、应用审核、验证码及风控处理属于仓库停止条件，本功能只准备本地安全绑定材料。
- 本功能配置 Provider 和账号，但不改变现有 Fake-first 路由，也不自动启用任何真实外部调用。
- 浏览器与 API 之间的传输沿用当前本机同源部署；远程部署时必须在独立任务中增加传输层和访问控制。
